# 0009. Розгалуження: дерево замість лінійного стеку

**Статус:** Accepted · замінює модель з [0002](0002-navigation-model.md), узагальнює [0003](0003-collapse-rule.md) і [0004](0004-layout-and-camera.md)

## Контекст
У лінійному стеку клік по іншому айтему тієї ж ноди **замінював** гілку праворуч. Нова вимога: різні айтеми однієї ноди створюють **окремі зв'язки**, і кожна наступна картка відкривається **під** попередньою сестринською. Так можна порівнювати, наприклад, Revenue і Expenses одного звіту.

## Рішення

### Модель (замість 0002)
```ts
type TreeNode = { key: string; ref: EntityRef; via?: string; parent: string | null; children: string[] };
type NavState = { nodes: Record<string, TreeNode>; root: string; focus: string; seq: number };
```
- `open(from, ref, via)`: якщо в `from` уже є дитина з тим самим `ref`, лише фокусуємо її. Інакше додаємо **нову дитину в кінець** `children` і фокусуємо її. Старі гілки не зникають.
- `focus(key)`: переносить фокус.
- `close(key)`: видаляє вузол з усім піддеревом; якщо фокус був усередині, він переходить на батька. Корінь не закривається.
- Ключі `n0, n1, …` з лічильника `seq`: одна сутність може бути в дереві кілька разів.

### Правило згортання (узагальнення 0003)
Розгорнуті лише:
- **фокус** і його **батько**;
- **сестри фокуса** (інші діти батька), щоб сусідні гілки лишались видимими картками;
- **діти фокуса**.

Усе інше, зокрема дідусь (2 кроки назад) і онуки (2 кроки вперед), згортається в іконку. Для лінійного ланцюжка це те саме правило ±1, що й раніше.

### Лейаут (узагальнення 0004)
- **x** — за глибиною: колонка `d` починається після найширших нод колонок `0…d-1` плюс `GAP`.
- **y** — «охайне дерево» з вирівнюванням по верху: перша дитина стоїть на рівні батька, кожна наступна нижче за все піддерево попередньої плюс `GAP_Y`.
- Висоти беруться з **виміряних** розмірів нод (ключ `id:e|c`, окремо для розгорнутого й згорнутого стану). Поки вимірів немає, використовується оцінка, і після вимірювання лейаут перераховується.
- Камера робить `fitView` по розгорнутих нодах лише тоді, коли всі висоти вже виміряні, щоб не «стрибати» двічі.

### Клавіатура
← батько, → остання відкрита дитина, ↑/↓ сестри.

## Наслідки
- `useNav().openedNext` замінюється на `openedChildren`, і посилання підсвічується, якщо його сутність відкрита будь-якою гілкою цієї ноди.
- Хлібні крихти показують шлях від кореня до фокуса.
- Розгорнутих нод тепер може бути більше трьох (усі сестри). Це свідомий компроміс заради порівняння гілок.
